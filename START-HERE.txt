================================================================================
                       AEON - START HERE (Phase 0, session one)
================================================================================

Goal of this first session: a kernel that boots in QEMU and prints over the
serial port. Everything below is setup + one working "hello". Full Phase 0
details: aeon-os-blueprint.txt, Part 5, "PHASE 0 - BARE-METAL ON-RAMP".

STEP 1 - INSTALL THE TOOLS (Fedora)
  sudo dnf install qemu-system-x86 gdb xorriso make git
  Then download a Zig release from ziglang.org/download (grab the linux
  x86_64 tarball, unpack it somewhere like ~/tools/zig, put it on PATH).
  Write the exact version you installed into a file named .zig-version in
  this folder - that pin is a project rule (blueprint Part 3).
  You do NOT need Odin, TLA+, swtpm, or TinyGo today - they arrive in
  later phases.

STEP 2 - GET THE LIMINE BAREBONES TEMPLATE
  Search: OSDev wiki "Limine Bare Bones". It walks you through a minimal
  bootable kernel: Limine bootloader config, a linker script, and a tiny C
  entry point. Adapt its build to use "zig cc" as the C compiler (the
  blueprint's Z1 decision) with the freestanding x86_64 flags the wiki
  shows. Build the ISO with xorriso, boot it with:
    qemu-system-x86_64 -cdrom yourimage.iso -serial stdio
  The -serial stdio flag is the important one: it connects the VM's serial
  port to your terminal.

STEP 3 - PRINT OVER SERIAL
  The template prints to the framebuffer; your real console is the serial
  port (a 16550 UART - OSDev wiki "Serial Ports"). Get one character out,
  then a string, then write your own minimal printk supporting %s %d %x %p.
  Serial printk is your debugger, logger, and best friend for the entire
  project.

STEP 4 - COMMIT
  git init, commit the working hello. From now on: small commits at every
  green state (blueprint rule R7).

THE REST OF PHASE 0 (next sessions, in order - details in the blueprint):
  - GDT, then IDT with exception handlers - make the page-fault handler
    print the faulting address (CR2), instruction pointer, and error code
  - the interrupt entry/exit assembly trampolines
  - PIC 8259 + PIT timer ticks, then PS/2 keyboard echo

PHASE 0 IS DONE WHEN: a deliberate null-pointer read produces a clean,
informative fault report over serial instead of a silent triple-fault
reboot.

RULES TO READ BEFORE WRITING ANY C: blueprint Part 4 (the discipline -
asserts, checksums, hosted-first testing, -Wall -Wextra -Werror from the
very first compile).

Log every session in docs/devlog.md - what you did, what broke, what you
learned. Begin.
